# YourTJ Wiki 编辑

让 Wiki 内容变更保留原意、符合页面结构，并通过仓库现有检查。下面的文件链接相对此 skill，命令均在仓库根目录执行。

## 确认任务与依据

- 阅读 [README](../../../README.md)、[贡献指南](../../../CONTRIBUTING.md) 和待编辑页面及相邻页面，沿用现有命名空间、目录和排序。
- 以当前 [CI 工作流](../../../.github/workflows/ci.yml)、[npm scripts](../../../package.json)、[Markdown 规则](../../../.markdownlint-cli2.jsonc)、[中文排版规则](../../../.textlintrc.json) 和[链接规则](../../../.lychee.toml) 为检查依据；配置变更后相应调整执行命令。
- 先用 `git status --short --branch` 确认工作区。只诊断时保持只读；编辑时保留无关改动。提交、推送、创建 PR、留言和合并分别以用户已有授权为准，不重复索要已有授权。
- 校区、地点、开放时间等事实使用用户提供的信息或可核实来源；缺失信息保留明确的待补充标记，存在影响内容含义的歧义时询问用户。格式修复不要顺带改变事实或语气。

## 编辑页面

正式页面放在现有顶层命名空间目录下。需要新增命名空间时按贡献指南先讨论。`.agents/` 是仓库工具目录，不是内容命名空间。

页面使用 YAML frontmatter；`title` 必填，`order` 和 `description` 按需要保留或填写。**frontmatter 的 `title` 已算文档主标题，正文从 `##` 开始**，下一级用 `###`，不要再加 `#` 或跳级。例如：

```markdown
---
title: 乐器
order: 120
description: 校内乐器的分布情况
---

## 四平路校区

| 地点 | 具体位置 | 使用时间 | 备注 |
|---|---|---|---|
| 南校区 | 三教 701 琴房 | 待补充 | 仅供艺传学生使用 |
```

- 清理意外的行尾空格；需要 Markdown 硬换行时才保留两个空格。标题、表格、列表和代码块周围留空行，代码块标注语言。
- 中文与英文、数字间按现有中文排版规则留空格；引号和括号配对。表格内的竖线按 Markdown 语法转义。当前规则允许长行、中文标题标点和紧凑表格，不为这些额外重排全文。
- 图片和附件放在 `assets/`，从页面所在目录写相对路径。页面间链接指向实际 `.md` 文件；亲自确认本次改动涉及的目标存在，不把外链检查通过当成相对链接已验证。
- 移动或重命名页面、目录会改变 URL；搜索并更新仓库内引用，说明路径变化，不承诺旧链接自动重定向。不要在修复排版时重命名页面。

## 执行与 CI 一致的检查

使用 Node.js 22+；首次准备环境或锁文件改变后执行 `npm ci`，不要为编辑文档顺带升级依赖。修复过程中可定向检查目标文件；交付或推送前运行完整的两个 npm 检查：

```bash
npm run lint:md
npm run lint:zh
git diff --check
```

这两个 npm 命令也是 CI 的入口，并包含 `.agents/` 下的 skill 文档。检查工具与锁文件版本保持一致。

已安装 lychee 时，可按 CI 参数运行链接检查：

```bash
lychee --config .lychee.toml --no-progress "**/*.md" ".agents/**/*.md"
```

本地没有 lychee 时，说明该项未运行，发布后查看 GitHub Actions 结果；不能据此声称全部 CI 已通过。检查新增链接及本次改动涉及的相对路径，不擅自扩大 `.lychee.toml` 的排除范围来掩盖失败。

## 定位失败并交付

处理已有 PR 时，先确认其最新提交和检查状态。以下变量填写实际 PR 编号和失败运行编号：

```bash
gh pr checks "$wiki_pr_number" --repo YourTongji/YourTJ-Wiki
gh run view "$wiki_run_id" --repo YourTongji/YourTJ-Wiki --log-failed
```

按日志中的文件、行号和规则修复，不靠反复重跑碰运气：

| 失败项 | 处理方式 |
|---|---|
| `MD025` | 页面已有 frontmatter `title` 时，将正文一级标题改成 `##`，并保持子标题层级连续 |
| `MD009` | 删除意外行尾空格，保留有意使用的两个空格硬换行 |
| 中文排版 | 按日志调整空格或成对符号，复查是否改变原意 |
| lychee | 核对报告中的 URL、HTTP 状态或超时；区分失效链接与网络限制，已有排除项以配置为准 |

前面的步骤失败会使后续步骤跳过；`skipped`、等待批准和执行中都不等于通过。修复后验证最新提交，不沿用旧提交的成功结果。

获得发布授权后，新 PR 从远端最新默认分支创建工作分支，目标为 `main`；更新已有 PR 时确认实际来源仓库和分支，尤其是 fork。仅提交任务文件并普通推送，不直接推送 `main`，不默认重写历史或合并 PR。

发布后确认 PR 的提交与推送结果一致，查看新一轮 CI，失败时继续定位与本次任务相关的问题。交付时报告修改内容、实际运行的检查及结果、未完成的检查，以及已创建的 PR 或提交链接。
